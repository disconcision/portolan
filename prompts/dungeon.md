Dungeon: rooms, creatures and a turn loop, organized as modules with nested modules, built on algebraic data types.

Pls build a small dungeon simulator incrementally, testing each step, and keep each concern in its own module with nested modules where it helps. Start with the world: a module for grid positions (a Pos type, neighbors, manhattan distance) and a module Dungeon with an ADT of tiles (floor, wall, door with an open/closed flag, stairs), a Room type built from tiles, and a nested module for carving (a function that places walls around a floor rectangle, one that cuts a door). Next: creatures as an ADT with distinct payloads (a player with hit points and an inventory, monsters of a few kinds with different stats, a trap that is not really a creature but sits in the same list), in a module Creatures with a nested module for combat (attack resolution, damage rules that depend on the creature kind) and a nested module for items (an Item ADT and an apply function). Next: the turn loop in a module Turn: a Command ADT (move in a direction, attack, use an item, wait), a State type tying a Room to its creatures and a turn counter, step : (Command, State) -> State that consults Dungeon for passability, Creatures.Combat for fights and Creatures.Items for item use, and a log of Event ADT values describing what happened. Then refactor: pull the damage rules out of Creatures.Combat into a new top-level module Rules with its own nested module for critical hits, and repair every caller; also change the door tile to carry a key requirement and fix everything that breaks. Finally a Render module with describe : State -> String that draws the room as text with creatures placed on it, and a short scripted game of five commands with tests on the final state and on the event log.

This is an OCaml project: use OCaml modules (nested `module … = struct … end` where the text says nested module), variants for the ADTs, and curried functions where the text writes a tuple argument.
